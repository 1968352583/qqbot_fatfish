# QQ 官方单聊最小联调

需求基线：[GitHub Issue #1](https://github.com/1968352583/qqbot_fatfish/issues/1)。2026-11-12 已完成本机鉴权、C2C 入站、三条独立气泡、WAV 语音条播放和窗口内外普通主动消息的真实账号验证，用户已确认客户端收到。窗口外结果来自断线后的单次补测，静默时间由平台最后消息时间和用户确认共同支持，详见下文。

## 验证目标

分开记录四层结果：凭据能鉴权、平台接受发送请求、QQ 客户端实际显示/播放、窗口外普通主动消息可送达。不能用前一层成功代替后一层。

本工具使用固定文本和短音频验证 QQ 通道，不调用付费语言模型或云语音服务。首轮 WAV 样本由本机系统语音合成生成，已实测以语音条送达并可播放；其他格式仍需单独验证。

## 准备

1. 在 QQ 开放平台为已创建的机器人配置自己的内部体验 QQ，能打开机器人单聊。当前指南支持最多 20 个内部体验号码，本项目首期只使用已确认的 1～5 人范围。
2. 采用 WebSocket 接入。如后台已设置 IP 白名单，将本机出口 IPv4 纳入允许范围。无需给本机配置公网 Webhook。
3. 运行 `bash .local/setup-qq.sh`，或参照 `.env.example` 创建 `.env.local`。需要 `QQ_APP_ID`、`QQ_APP_SECRET`，不使用旧版 Token。

向导仅保存本机凭据并核对体验成员，不重置密钥、不充值、不发送 QQ 消息。文件模式为 0600；`.env.local` 和 `.local/` 均已加入 `.gitignore`。

## 步骤

以下命令在项目根目录运行。`scripts/qq-smoke.sh` 仅对当前测试进程关闭环境代理并直连 QQ，不修改系统或用户的代理设置。直接运行 Node 时，也应避免启用 `--use-env-proxy` 或 `NODE_USE_ENV_PROXY=1`；本机代理路径的断线证据见下文。

### 1. 鉴权与获取网关

```bash
bash scripts/qq-smoke.sh check
```

通过标志：提示凭据与获取网关成功。工具兼容数字/字符串形式的 token 有效期，并识别 HTTP 200 中的业务错误。

### 2. 接收入站事件并绑定测试用户

```bash
bash scripts/qq-smoke.sh listen
```

终端显示一次性口令，例如 `/验证 123456`。用自己的测试 QQ 向机器人发送该口令；终端确认收到后，保持此进程运行。

首次匹配口令前不绑定任何人；绑定后只记录该 QQ 的消息 ID、平台时间与附件类型，不保存正文或参考转写。可以再发送一条语音或普通图片，验证附件是否到达；这不等同于图像理解或语音转写质量通过。

本工具收到网关重连指令或可恢复断线时自动重连，优先用原网关会话和已处理序号 RESUME，保持测试 QQ 绑定。短时间内连续恢复最多尝试五次，超过上限或平台终止连接权限时退出。不能续接而重新鉴权时，连续监听时间重新计算。进程重启仍需新口令，尚未实现持久会话恢复、进程守护和完整生产运维。

### 3. 三条独立回复

在另一终端运行：

```bash
bash scripts/qq-smoke.sh reply
```

必须在收到测试消息后的四分钟内执行，避开当前文档的五分钟/六十分钟窗口矛盾。检查 QQ 中是否出现顺序正确的三个独立气泡。工具为同一入站消息递增 `msg_seq`，最多预留四次回复；网络结果不确定时不重用序号。

也可在第二个气泡发送前插话，确认工具停止尚未发送的测试文本。平台已接受的在途消息无法保证撤回；完整产品还需实现根据新输入重新生成回复。

### 4. 发送语音条

先在 QQ 中发一条新的测试消息，再运行：

```bash
bash scripts/qq-smoke.sh voice .local/qq-smoke.wav
```

也可提供自己的小型 `.silk`、`.mp3` 或 `.ogg` 文件。首轮文件限制为 1 MB 以内，避开上传文档对 5M 计算口径的不确定性。工具上传 Base64、设置 `srv_send_msg=false`，再显式发送一条被动富媒体消息。

验收须同时检查：是 QQ 语音条、可以播放、内容与样本一致。上传成功或消息 API 返回成功不能证明语音播放通过。

### 5. 普通主动消息

```bash
bash scripts/qq-smoke.sh proactive
```

该命令只向已绑定的测试 QQ 发送一条固定文本，不带 `msg_id`、`event_id` 或 `is_wakeup`，不尝试召回接口绕过普通主动权限。

立即运行只能测试普通主动请求形态。自动判定窗口外需至少 61 分钟无新消息，并有至少 61 分钟连续监听或成功续接的会话；工具同时检查平台事件时间、监听起点及发送期间的新消息/会话变化。重新鉴权造成的观测空白不能自动计入证据。即使记录 `outsideWindow=true`，仍需 QQ 客户端确认实际送达。

不自动反复试发，不让失败测试影响其他用户。若用户开启拒收或平台缺少主动权限，保留错误码作为结果，不将失败隐藏成成功。

### 6. 查看记录

```bash
node scripts/qq-smoke.mjs report
```

### 本次实测记录

2026-11-12，北京时间：21:09:03 收到验证口令；21:09:21～24 三条文本被 API 接受；21:09:36 语音被 API 接受；21:09:55 普通主动请求被接受。用户随后分别确认三条文本、语音播放和主动文本都正常。

原计划使用 `.local/wait-for-qq-window.mjs` 在 22:10:08 测试。实际在 22:04:37，直连持续约一小时后，网关发出 op=7，旧监听程序将其当作致命错误退出（随后关闭码 4009）；22:04:40 等待程序检测离线后终止。因此原定消息根本未发送，不能据此判断 QQ 主动权限失败。

用户报告未收到后，确认自 21:09 验证口令以来一直未再向机器人发消息。22:22:36 用原绑定账号进行一次恢复补测，不附 msg_id、event_id 或 is_wakeup；API 接受，用户确认实际收到。记录中的闲置时间为 73 分钟，证据标记为 `platform_timestamp_and_user_confirmation`，同时记录 `listenerGap=true`。这验证当前账号的一次窗口外送达，不证明全天任意频率主动发送或全部配额。

重连修复先回放 op=7：测试曾以相同退出错误失败，修复后通过。现将网关生命周期独立为 `scripts/lib/qq-gateway.mjs`：保存进程内 session_id 和已处理序号，指数退避、有限重试；成功 RESUME 保留观测起点，重新 IDENTIFY 则重置。另对真实网关进行一次受控断开，观察到 READY → reconnecting → RESUMED，未发送聊天消息。

等待程序现允许最多 90 秒的会话续接，只有恢复成功且观测起点未改变才继续；新消息、重新鉴权或恢复失败终止测试。它仍是临时单次验证工具，不是产品主动聊天调度器。本次等待及恢复补测均已结束，没有继续定时发送。

### 本机代理断线诊断

相同 Node.js 24 WebSocket 监听代码，通过 `--use-env-proxy` 两次连接分别持续约 119 秒、120 秒后失败。第二次在断开前已收到两次心跳 ACK，关闭码为 1006。只改变网络路径、清除该进程的代理环境变量后，直连超过同一断点并成功完成上述真实收发。

这支持将故障定位到本机代理路径相关的连接处理；尚未区分代理自身与 Node 代理实现，不据此声称所有代理均不可用。默认测试启动脚本采用已验证的直连路径。复现依赖真实网关与本机代理的约 120 秒连接行为，单元测试没有能覆盖该外部故障的有效测试边界；回归证据为相同监听程序的代理/直连对照及持续心跳。临时调试日志已从源码移除。

## 文档依据与已知差异

- [当前凭证接口](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/access-token.html)：使用 `https://api.bot.qq.com/app/getAppAccessToken`；官方 SDK 部分代码仍用旧域名，本工具依据当前官网。
- [WebSocket 接入](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/event-emit/websocket.html)与[网关接口](https://bot.q.qq.com/wiki/develop/api-v2/openapi/wss/url_get.html)：获取动态 WSS 地址，以 `QQBot` token、`1 << 25` intents 和单分片连接，并按 Hello 给出的周期心跳。
- [单聊消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)：当前页面存在五分钟与六十分钟表述冲突，基础回复在四分钟内完成，窗口外测试等待至少六十一分钟。
- [单聊文件上传](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_files.post.html)与[富媒体消息](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/rich-media.html)：上传细节列标准 SILK，概述另列 WAV/MP3/OGG；逐项实测，不预先宣称所有格式通过。
- [官方 SDK 媒体源码](https://github.com/tencent-connect/qqbot-nodejs/blob/main/src/protocol/api/media.ts)验证本地文件转 Base64 放入 `file_data` 的方式；本工具遵循当前上传文档携带文件名并使用更小样本。
- [官方接入指南](https://bot.q.qq.com/wiki/)：WebSocket 无需公网服务器；体验成员和平台权限仍须实际配置。
