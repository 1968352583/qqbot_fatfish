## 两个真实输入问题及修复

用户报告语音和图片触发「我这会儿有点卡住了」，图片还触发不支持附件提示。只记录附件字段结构的临时诊断显示：语音已有 `asr_refer_text`，图片实际来自 `multimedia.nt.qq.com.cn`，模型响应在 JSON 解析处失败。

此前允许的图片域名漏掉实际 QQ 媒体域名，已补充并继续限制 HTTPS、域名及大小；未放开任意地址。模型请求现在将历史助手气泡包装为与当前 JSON 输出相同的结构，并兼容代码围栏。无法得到有效结构时最多做一次自然文本恢复，不从恢复内容提取长期记忆，每次请求仍独立预留和结算预算。

DeepSeek [JSON Output 官方说明](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)确认 JSON 模式可能返回空白内容；[图片接口说明](https://api-docs.deepseek.com/zh-cn/guides/vision/)支持 Flash 图片输入。没有仅靠文档宣称问题解决：新增失败测试先复现两种提示，修复后通过，随后由用户再次在 QQ 确认两类内容均可理解。诊断没有保存附件 URL 路径、语音正文或原始图片；临时诊断代码已移除。

## 自然提醒修复（2026-11-13）

用户报告“早上8点叫我吃饭”被回复做不到。入口测试复现为自然表达落入普通模型，未创建提醒；当前主动开关确实开启（09:00～22:00，每日两次，间隔三小时），因此不是主动功能缺失或预算耗尽。

新增独立提醒解析与确认模块，支持今天、明天、后天、早晚时段、中文数字、半点，以及“叫我/喊我/提醒我”。缺失日期或早晚时先询问，确认后才持久保存；不将过期的明确日期偷偷顺延。确认按用户隔离，可取消，15 分钟超时；未确认状态在进程重启后需重新提出。

`node --test tests/reminders.test.mjs` 的原始失败测试先证明调用了普通模型，修复后验证从提出、确认、保存到八点发送的完整路径，且不会调用模型。加入时间解析与确认隔离/取消/超时/过期/重复要求保护。完整 `npm test` 现为 **31 项通过**。模型能力说明同步明确支持主动聊天和提醒，但不得未经程序确认就宣称已安排。

## 让约定融入聊天（2026-11-13 后续更新）

用户反馈提醒创建“看起来成功了”，但回执和逐步确认破坏了朋友聊天的感觉；明确同意省略日期时默认下一次该时刻，并在自然回应中带出实际日期。本次规则取代上一节中「只要缺少日期就追问」的做法，早晚不明或明确时间已过仍需澄清。

约定先写入数据库，再把真实执行结果交给模型，用当前角色和上下文接话。平时不展示编号或「已安排」；只有主动查询列表和后台保留管理信息。后续普通对话带入当前用户自己的待办约定，来源可追踪；要求遗忘时清理约定及相关派生回复。支持自然取消和完全相同约定去重。

到点文案与接话在同次模型生成中完成、持久保存，按时发送不再依赖模型；预算耗尽、合成失败或八秒没有完成生成时仍用固定自然话术。新列自动迁移，旧约定不丢失。新增测试覆盖保存先于接话、默认下一次、模型故障回退、到时零模型调用、自然取消、约定隔离与遗忘、旧数据库迁移、预备文案重启保留、发送中遗忘后不使用旧队列文案。完整 `npm test` 现为 **36 项全部通过**。

另以合成聊天调用真实 DeepSeek，得到不带任务回执的接话及到点文案，费用记入本月账本；没有重传已有私聊做诊断，也未向真实 QQ 自动发送该样例。用户实际复测仍觉得生硬，因此该版未通过体验验收。

## 默默记住，按人设接话（2026-11-13 再次调整）

用户指出，回复中严谨复述到几点几分仍像任务确认；希望保持人设、默默记住。这修正了上一版「回应必须包含实际时间」的要求，下一次时间的内部解析规则继续有效。

原代码同时在模型提示和发送校验中强制准确时间：即使模型给出一句自然回应，也会被替换为含完整时刻的固定话术。已移除两处限制，改为让角色按上下文简短接话，不强加报时、打趣、叮嘱或多条消息；只有用户询问时才说明具体时间。模型失败或预算不足时的备用回应也不再复述时间。

入口回归测试先复现自然回复被替换的问题，调整后覆盖绝对时间和「一分钟后」两种情况：短句原样发送、时间准确持久保存、到期前不发、到期后发送预备文案，且不再调用模型。完整 `npm test` 仍为 **36 项全部通过**。用合成对话复核真实 DeepSeek：前两次试答仍重复相对时间，调整表达指引后得到「好，包在我身上。」并生成独立的到点文案；各次费用计入账本，未读取已有私聊、未向 QQ 自动发送测试消息。本轮客户端体验尚待用户后续反馈。

## 云端迁移与自动部署检查（2026-11-14）

服务器使用 Node.js 24.14.1，由独立账号运行 `fatfish.service`，已启用开机启动和异常重启。向主进程发送 SIGTERM 后，systemd 自动重启成功，HTTP 与 QQ 网关均恢复健康。后台仅监听 `127.0.0.1:3210`，SSH 隧道已验证；本机启动脚本会阻止意外启动第二个实例。

应用发布入口已通过专用受限 SSH 密钥实际部署成功，运行版本为 `16a1c6f660c4b2bd0cf831438275b351062138c5`。健康检查同时确认版本和 QQ 网关状态。专用部署账号不能取得任意 shell。Breeze TTS 2 不适合当前 2 核、约 2 GB、无 GPU 的服务器，输出语音目前回退文字；依据见 [资源检查](../research/breeze-server-fit.md)。

GitHub Actions 中 36 项应用测试和 3 项发布包测试均通过，但 [自动发布运行](https://github.com/1968352583/qqbot_fatfish/actions/runs/43543618500) 因 SSH 连接超时失败，**尚未完成 CI/CD 验收**。本机经同一受限入口发布成功不能替代 Actions 成功。PR 只运行测试，部署环境只允许 `main`。

网络诊断已确认：GitHub 运行器的 SYN 请求到达服务器，服务器发出 SYN-ACK 应答，但运行器继续重传并超时；服务器主动访问 GitHub 也在 TCP 建连阶段超时。iptables、nftables 和路由检查未发现对应主机阻断，当前证据指向服务器之外的网络路径或云端策略，尚不能确定具体来源。没有因此关闭防火墙或扩大全网访问权限。任务 [#5](https://github.com/1968352583/qqbot_fatfish/issues/5) 保持未完成，等待打通网络并获得真实成功的 Actions 发布。

随后只读检查云控制台：实际关联的安全组允许 SSH 入站、出站默认全部放行；对应交换机未绑定网络 ACL，使用系统路由表且无自定义路由；云防火墙未开通，DDoS 基础防护状态正常。未找到可据此调整的阻断规则，需要继续由云服务商核对外部路径。诊断草稿仅保存在本机，尚未提交技术支持。

云端真实 QQ 聊天和到时提醒仍需用户验收；开机启动已启用，但未为此重启承载其他服务的整台服务器，全天稳定性需要继续观察。

## 百炼语音接入（2026-11-14）

云端新增 Qwen-Audio-3.1-TTS-Plus，通过北京地域业务空间 API 合成 24 kHz WAV。服务器直连合成和 OSS 下载均返回 HTTP 200：首条 111,404 字节，约 0.84 秒；部署后经生产管理员试听接口生成 176,684 字节，约 1.19 秒。这是单次短句结果，不是延迟保证。后台试听不会向 QQ 自动发消息。

应用版本 `9803b246498518b52ec4b4b39790425825b4dcb4` 已通过受限 SSH 入口上线，QQ 网关 ready，systemd active/enabled。百炼凭据文件为 `600 fatfish:fatfish`，后台仍只监听 `127.0.0.1:3210`。部署前创建一致性 SQLite 备份并通过完整性检查，保留已有成员、聊天与约定；没有上传这些数据到 GitHub。

初始使用现成音色 `longanhuan_v3.1`，启用自动情绪指导并恢复全局 10% 自动语音选用概率，个人设置继续覆盖。用户在 QQ 实际收到并能播放语音，但反馈声音或语气需要调整；功能链路已确认，听感尚待按偏好调整。

后台增加默认语气、语速、音调、音量、自动情绪开关，以及试听和描述式音色设计；生成声音后需主动选择才替换。模型的语气指导单独传给 TTS，不写入聊天或记忆。合成失败按原机制回退文字，合成已完成但下载失败仍计费；结果不明保留估算，明确拒绝归零。

44 项 Node 测试和 3 项发布包测试通过，新增覆盖参数与密钥隔离、预算和失败计费、下载域名与文件限制、情绪开关、音色设计不自动采用、语气与聊天分离、管理员鉴权。使用合成数据的浏览器预览已核对字段和音频播放器。API 及设计能力以[百炼合成文档](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-http-api)、[音色设计文档](https://help.aliyun.com/zh/model-studio/voice-design-api-references)为准。

### 可爱俏皮风格调整

用户进一步希望声音可爱、俏皮，并要求查找大肥鱼相关资料。依据[原始角色与语音项目调查](../research/fatfish-voice-style.md)，使用百炼描述式音色设计创建原创声音，方向为清亮轻软、带笑意、轻巧放松、偶尔小得意；安慰时放轻放慢，认真时收住玩笑。没有下载或克隆社区声库录音。已将专属音色和默认语气保存到服务器设置，继续允许后台自定义；不更改既有聊天、角色关系或个人偏好。

生产音色设计返回成功，预览 335,560 字节；随后使用该音色和语气实际合成 387,884 字节。检查发现百炼下载的完成 WAV 仍带流式长度占位值，会使部分读取器误报时长。适配器现按完整下载的字节数修正 RIFF/data 长度，保留 PCM 内容，并检查 24 kHz、单声道、16 位 PCM 结构；新增真实头格式回归测试后 **45 项 Node 测试通过**。新声音的主观听感仍交由用户试听评价。

GitHub [本次运行](https://github.com/1968352583/qqbot_fatfish/actions/runs/43565518860) 中应用测试、发布包测试和 Shell 检查成功，但自动发布仍在 SSH 22 端口建连时超时。本次应用通过已有受限 SSH 入口实际部署，不能将其记录为 GitHub 自动发布成功。
