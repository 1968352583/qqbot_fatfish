状态更新（2026-11-13）：已确认需求并完成首个本机版本，采用 Node.js 24、SQLite、DeepSeek Flash 和管理员网页。用户已在 QQ 实测确认文字、语音输出、语音输入与普通图片理解。首期规格见 [Issue #1](https://github.com/1968352583/qqbot_fatfish/issues/1)，通道联调见 [Issue #2](https://github.com/1968352583/qqbot_fatfish/issues/2)，产品实现见 [Issue #3](https://github.com/1968352583/qqbot_fatfish/issues/3)。窗口外普通主动补测也已被 API 接受且用户确认收到；静默时间依据平台记录和用户确认，存在监听空白。云端部署和云端语音仍待完成。最新证据见[应用验证](../validation/app.md)与[通道联调记录](../validation/qq-c2c.md)；下文调查与访谈保留当时背景。

## 已确认的范围

根据用户在本项目中的明确说明：

- 在 QQ 单人聊天中实现“养大肥鱼”的体验。
- 希望机器人能够发送语音、连续发送多条消息、主动找用户说话；需要调查这些能力是否可行。
- 不需要机器人操作其他软件。
- 最初范围为讨论需求和核实可行性；需求确认后用户同意技术验证并继续实现，当前已运行本机版本，尚未部署云端。

| 范围 | 首期要求 |
| --- | --- |
| 使用范围 | 1～5 名受邀用户，分别在 QQ 单聊中使用；最终云服务器全天在线。优先采用 QQ 官方机器人，先验证目标账号能力；不包含群聊或操作其他软件。 |
| 角色与关系 | 大肥鱼风格，活泼、亲近、会接梗、有一点调皮，初始为朋友式陪伴。共享可修改的基础角色卡，各用户分别积累记忆、关系与相处习惯。 |
| 输入与回复 | 接受文字、语音和普通图片，表情包尽量理解；不确定时询问或说明。一次回复通常 1～3 个自然气泡，用户插话时暂停未发送内容并重新组织。 |
| 语音输出 | 默认文字；支持用户要求语音和角色偶尔自行选用语音，自动语音可关闭。先用可替换的现成普通话音色，通常 5～20 秒，可选择附文字；语音失败回退到对应文字。 |
| 主动聊天 | 支持话题回访和自主开话题，按主动开场次数计数，一个开场多个气泡仍算一次；每日次数、时段、间隔、忙碌和未回复规则可自定义，也可完全关闭。 |
| 一次性提醒 | 支持创建、查看、取消，时间含糊时问清；与主动闲聊分别管理。恢复可发送时，仅补发距原定时间不超过默认 10 分钟的提醒，注明迟到；超过标为已错过并在后台显示，时限可修改。主动闲聊不集中补发。 |
| 记忆与保存 | 自动积累明确表达的偏好、称呼和重要经历，也接受明确记住的要求；猜测或不确定转写不直接成为事实。用户可查看、更正、要求忘记；原始对话默认保留 30 天，长期记忆持续保留，媒体处理后不长期保存。更正和遗忘同步处理相关旧内容，不能再次提取回来。 |
| 管理员网页 | 仅项目拥有者登录；管理角色、表达、主动规则、语音、成员、个人偏好、记忆保留、提醒、用量与预算。可查看所有用户的保留聊天与记忆正文，更正或删除任意用户的长期记忆，以及删除聊天记录；原始聊天正文不改写。 |
| 个人设置 | 普通用户通过 QQ 调整自己的偏好。个人设置优先于全局默认，修改全局默认保留已有个人选择，支持恢复默认；全局停用和预算限制仍统一生效。 |
| 费用控制 | 初期总预算目标 100 元/月。预留服务器固定开支和余量后，对可变调用额度在 80% 时提醒，90% 时暂停话题回访、自主开话题和自动语音，额度用尽时暂停新付费 AI 请求。金额和阈值可修改，管理员提高额度或进入下月后按其他有效条件恢复；后台、设置和既有纯文字提醒可继续工作。 |

### 初始可调参数

| 参数 | 初始值 |
| --- | --- |
| 主动聊天允许时段 | 北京时间 09:00～22:00 |
| 每日主动开场次数上限 | 2 次 |

| 连续未回复后的暂停 | 连续两次主动开场未回复，暂停主动聊天 24 小时 |

| 一次性提醒补发窗口 | 距原定时间不超过 10 分钟 |
| 总预算目标 | 100 元/月；调用额度的具体金额待核算固定费用后配置 |

这些参数是首期默认值，不是不可更改的限制。具体模型、音色、服务器配置、页面布局和气泡节奏细节在后续设计及试用阶段确定。真实 QQ 账号权限、接口表现与完整费用仍须验证；预算保护不承诺供应商账单绝无计量延迟或超额。

2026-11-13 体验补充：用户希望约定像朋友聊天，自然接住并记得，不显示任务回执。「早上 8 点」未说日期时默认下一次早上 8 点，只在早晚等确有歧义时追问。实际体验后用户进一步明确：不需要在回复中严谨复述日期和时刻，保持人设、默默记住即可；这取代此前「自然说明今天或明天」的回复要求。编号仍保留在主动查询和后台，日常对话隐藏。

## “养大肥鱼”的含义

在本次检索到的 QQ / AI 语境中，“大肥鱼”指与 DeepSeek 蓝鲸形象有关的拟人角色；“养”通常指给模型配置角色身份、说话习惯和持续记忆，使其成为可以长期交流的 AI 伙伴。这个解释来自下列官方演示与社区原始项目的交叉印证；它不是一个有统一规格、统一实现的产品名称。

腾讯 QQ 于 2026-10-27 发布《听说最近大家都在QQ养大肥鱼！》，介绍将“大肥鱼”接入 QQ，简介包含 DeepSeek Harness 相关标签，并分别署名角色原型、女仆装二次设计和 Q 版参考的创作者。该来源可以证明 QQ 官方已经使用这个说法并介绍接入玩法，但不能据此把所有社区人格设定认定为官方设定。[腾讯 QQ 原始视频](https://www.bilibili.com/video/BV17rxT6UEpH/)

腾讯组织维护的 `dsh-qqbot` 仓库明确说明其功能是把 DeepSeek Harness 的 AI 助手接入 QQ 私聊与群聊；DeepSeek 官网则将 Harness 描述为可通过插件扩展的开源 agent 运行环境。这是已有的一条接入路径，并不证明本项目必须采用 Harness。[腾讯 dsh-qqbot 仓库](https://github.com/tencent-connect/dsh-qqbot)、[DeepSeek Harness 官网](https://www.deepseek.com/en/harness/)

社区项目 `YuanZ1949/dafeiyu-bot` 将“大肥鱼 / Deepseek娘”描述为能够接梗、记事并偶尔插话的 QQ 角色，列出聊天记忆持久化、私聊和定时提醒等功能。另一个社区项目 `kylian-08/dafeiyu-qq-bot` 列出人格卡、长期记忆、分条回复和主动冒泡。这些第一手项目说明支持“持续陪伴与个性表达”这一语义；本次未运行项目，不能把 README 声明视为已经验证的可靠性结果。[dafeiyu-bot](https://github.com/YuanZ1949/dafeiyu-bot)、[dafeiyu-qq-bot](https://github.com/kylian-08/dafeiyu-qq-bot)

部分社区项目还让角色在 B 站等平台活动。例如 `dsh-dafeiyu-life` 自述包含长期记忆、可塑造人格和社交机制，并明确将情绪与意愿描述为系统模拟。跨平台活动是这些项目的额外能力，不在用户已确认的本项目范围内。[dsh-dafeiyu-life](https://github.com/minedalang/dsh-dafeiyu-life)

### 当前产品方向

当前确认后，产品方向可以概括为：

> 一个供少量受邀用户分别在 QQ 单聊中交流的陪伴角色：基础人设一致，记忆和相处习惯分别积累；能理解文字、语音和普通图片，用有自然节奏的短消息或语音回应，并按个人偏好主动开场。

可供后续验收讨论的示例：用户昨天提到今天有面试，机器人在合适时段主动询问进展；用户回复后，机器人接着发送几条短消息，必要时发送语音。话题回访的方向已确认，具体触发时点、消息节奏和语音选择规则仍待细化。

## 消息能力与接入方式

调查结论：三类能力都有技术实现路径。官方 QQ 已有语音、同一消息多次回复及主动发送机制；本项目现已实测三条气泡、WAV 语音条播放和窗口内外普通主动文本。窗口外为一次 73 分钟后的恢复补测；具体配额与长期在线仍需验证。具体框架与模型尚未确定。

### 接收语音与图片的事实补充

当前单聊事件的附件结构支持语音与图片，语音附件包括 `voice_wav_url` 和 `asr_refer_text`（语音识别参考结果）。因此语音输入可以先评估平台参考转写，不能预先断定必须额外购买识别服务；同时，文档没有保证每条语音均有有效转写，也没有承诺准确率。转写缺失或不清楚时需要明确的交互处理，是否采用独立识别服务属于后续选择。[单聊消息事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/c2c_message_create.html)

图片附件可以供应用进一步识别，这是根据附件能力作出的实现推论；QQ 本身不保证提供图像理解结果。普通图片、GIF、QQ 系统表情、自定义表情包和对消息的表态需要分别区分，当前证据不支持承诺完整覆盖所有表情形态。第二轮已确认首期接受语音和普通图片，表情包采用尽力理解的范围，实际能力仍待验证。[消息类型](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/type/overview.html)

### 月费用示例（2026-11-12 核对，非选型结论）

以下是假设用量的算例，不是用户已确认的用量、预算或完整月账单：按 30 天，1～5 名用户合计每日 100 次模型调用，每次平均输入 4,000 token、输出 200 token；每日合计合成约 2,000 个汉字。不计缓存优惠、赠送额度与促销。

| 项目 | 计算 | 月费用 |
| --- | --- | --- |
| DeepSeek Flash 文本调用 | 输入 `100 × 30 × 4,000 = 1,200 万 token`，输出 `100 × 30 × 200 = 60 万 token`；输入未命中缓存单价为空闲/高峰 1/2 元每百万 token，输出为 4/8 元 | 全部空闲约 14.40 元；全部高峰约 28.80 元 |
| CosyVoice v3 Flash 现成音色，北京地域 | 1 元/万计费字符；每个汉字计 2 个字符：`2,000 × 30 × 2 ÷ 10,000 × 1` | 约 12 元，标点等另产生少量字符 |
| 上述两项合计 | 文本模型调用 + 语音合成 | 约 26.40～40.80 元 |

价格来源：[DeepSeek 官方价目](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[阿里云百炼官方价目](https://help.aliyun.com/zh/model-studio/model-pricing)。所用模型仅作算例，不代表已比较所有模型的价格或角色表现；单价可能改变。

输入的 4,000 token 应包含人设、历史和记忆文本；输出的 200 token 应覆盖全部计费输出，此例可理解为非思考模式。若记忆整理、主动选题、重试或思考输出超出上述用量，须另计。图片按尺寸换算成 token 并计入输入；当前 Flash 文档规定单图最多 1,024 token，若每月额外输入 3,000 张达到上限的图片且各只输入一次，增量约为 `3,000 × 1,024 ÷ 1,000,000 × (1～2)`，即 3.07～6.14 元；重复携带图片也计入输入。[图像计费说明](https://api-docs.deepseek.com/zh-cn/guides/vision/)

该算例未计云服务器常规续费、独立语音识别、存储、流量、备份和定制音色，也不是所有输入都能准确理解的质量承诺。完整预算需要结合实际人数、聊天量、声音选择与部署方案继续核算。

### 超出预算的含义（Q20 事实补充与已选策略）

预算目标、程序控制的调用额度和供应商账户余额是不同概念。仅记录一个月度目标不会自动停止调用或改变真实账单；程序需要另行实现提醒和阻止新付费请求的规则。第四轮已选择 100 元/月的初期总预算目标和分级保护，实际配置尚未实施。

供应商事实：DeepSeek 账户余额不足时返回 HTTP 402，无法继续正常调用；赠送余额耗尽但充值余额仍足够时不等于停服。[错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)、[扣费规则](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

阿里云百炼可设置预算告警，并另行开启“达到预算后立即停止”，使适用维度的按量调用在达额后受限；只设告警不等于启用停止。该功能仅覆盖按调用量费用，不覆盖训练、PTU、DTU 等，且 PTU 溢出和通过其应用产生的调用暂不支持自动停止；停止存在延迟，延迟期间仍计费，不能视作绝无超额的保证。[预算管理](https://help.aliyun.com/zh/model-studio/budget-management)

已选择的应用方案：先预留服务器等固定开支和费用余量，单独设置模型、语音等可变调用预算；调用额度 80% 提醒、90% 暂停话题回访、自主开话题和自动语音、额度用尽时阻止新付费请求。后台、配置和无需模型生成的既有文字提醒可继续运行，仍受 QQ 发送权限等条件限制；停止模型调用不会消除服务器开支。管理员提高额度或进入下个月后可恢复，但不能绕过供应商余额、平台权限和其他有效停用条件。

### 首期验收场景草案

以下场景将已确认需求转成后续可检查的结果，尚未执行测试：

| 场景 | 预期结果 |
| --- | --- |
| 用户甲告诉机器人一件私事，用户乙随后聊天 | 乙的回复不引用甲的私人信息；管理员登录后台可以分别查看两人的保留记录和记忆 |
| 修改主动聊天全局默认，但甲已有自己的频率 | 甲保留个人选择，未自定义的用户采用新默认；全局停用仍能阻止所有人的主动聊天 |
| 机器人准备发送多个气泡，用户在中途插话 | 暂停未发送的内容，结合新输入重新组织回应；已发出的内容不被假定自动撤回 |
| 用户发送语音或普通图片 | 能处理时理解并回应，不确定时询问或说明；不将不确定内容直接存为事实 |
| 用户更正或要求忘记一条信息 | 后续回答不再依据旧事实；后台和后续记忆提炼不能从旧记录恢复已删除内容 |
| 管理员更正乙的长期记忆或删除乙的聊天记录 | 指定用户的数据及相关派生内容按规则更新，不影响甲；原始聊天正文不提供改写操作 |
| 语音合成或发送失败 | 回退到对应文字，不重复生成一段无关回复 |
| 到达调用额度预警、降级和停止阈值 | 依次提醒、暂停非必要自动交互、停止新付费 AI 请求；设置和已有纯文字提醒仍按条件工作 |
| 八点提醒因故障未发送，八点零五恢复可发送 | 补发并注明迟到；不会重复发送多份 |
| 八点提醒因故障未发送，八点四十恢复可发送 | 标记已错过并在后台显示，不补发；主动闲聊也不集中补发 |
| 重启后检查个人设置、记忆和提醒 | 已确认的设置及保留内容持续存在；到期或被删除内容不因重启复活；按配置的补发窗口处理错过时间的提醒 |
